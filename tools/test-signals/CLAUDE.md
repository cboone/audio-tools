# Exact test signals

Read `README.md` first. It carries the problem statement, the usage, the four decisions that shape the output, how the readback verification works and why it is split in two, the worked example this tool was adopted from, and the known limitations.

The readback is the point of the tool, not a convenience on top of it. A generator that silently clipped its own output would produce a level sweep that tested nothing, and every number measured with it would be a claim about a file nobody checked.

## Notes for agents

- **Do not collapse the two verification checks back into one tolerance.** Comparing the file's peaks against the in-memory array's peaks is exact and catches a bad write. Comparing the in-memory peak against the requested level is a different question whose honest answer depends on the waveform and the frequency. The bash script this replaces conflated them at 0.0005, which passed only because every frequency it shipped divides 48 kHz evenly; at 16 kHz against 48 kHz a correct sine peaks 13.40% low. One tolerance cannot be both exact enough to catch a clipped write and loose enough to accept a correct file.
- **Do not tighten the floors.** `sine_floor`, `saw_floor` and `gated_floor` are worst-case bounds over phase, not estimates of what a given file will actually reach. A long file usually lands far closer to the crest than the bound allows. Making them tight would start rejecting correct files, which is the failure the split was introduced to fix.
- **Do not add a flag to skip verification.** Every file is checked, unconditionally, and there is nothing to trade off: the check costs one read of a file that was just written.
- **`--levels` and `--saws` take strings, not floats, and that is deliberate.** The filename is made from the literal token the caller typed. Parsing them as floats gives `level-0.01.wav` for `0.010` and `saw-0.9.wav` for `0.900`, which silently renames the files a caller's own procedure refers to by name.
- **Do not fade these signals.** `tools/sampler-nulltest/maketest.py` fades because an abrupt start is broadband content that would contaminate a transfer-function measurement. Here the requirement is the opposite: the file must hold an exact peak for its whole length, and a fade would make the level check depend on where the peak happened to land. The two tools disagree on purpose.
- **The Fósforo levels are not defaults and must not become defaults.** `1.050` and `1.089` bracket `trace_rail / trace_full_scale` from one plugin's `src/gpu/iface.zig`. Any other instrument has a different threshold, or none. They belong on the command line, and `README.md` shows the invocation.
- **The screenshot analyser is not coming here.** Issue [#1](https://github.com/cboone/audio-tools/issues/1) floated adopting `measure-trace` alongside the generator. [cboone/fosforo#64](https://github.com/cboone/fosforo/issues/64) settled that it stays in that repository, and the reasoning holds: it restates `trace_full_scale`, `trace_rail` and two shader colour literals that it does not own, it cannot measure any other oscilloscope, and its only real safeguard is a test that reads the script and checks those constants against the Zig source, which can only exist there. The admission criterion this repository states for itself is that the *analysis* be general; that one is a display contract restated in Python.
- **There is no test suite.** Validate any change by rendering and checking the result, and by proving the verification still fails when it should. The cases used so far: render the full default set and confirm 20 files with the expected peaks; render with fosforo's parameters and compare every file against `~/Music/fosforo-test-tones`, which the original ffmpeg script produced and which the port currently reproduces bit-identically; read `level-2.000.wav` back and confirm WAV format tag 3, 32 bits, and samples above unity; render a frequency that does not divide the sample rate, such as 16 kHz against 48 kHz, and confirm the shortfall is reported rather than failed; render above Nyquist and confirm it is refused. Then inject each of these faults into a copy and confirm each exits 1: writing `int16`, clamping to unity, rendering `pan-hard-right` into both channels, and rendering a level louder than requested.
- **Output is not committed here**, unlike `tools/sampler-nulltest/probe/*.wav`. Those are fixtures that real bounces were made from and that the analysis compares against. These are 20 files of roughly 7.7 MB that nothing compares against and that regenerate in seconds, so `.gitignore` carries `tools/test-signals/*.wav` instead.
- The script carries PEP 723 inline metadata and a `uv run --script` shebang, so `uv run maketones.py` or `./maketones.py` needs no environment setup. System `python3` has no `scipy`, so plain `python3 maketones.py` will fail.
- Frequencies are refused at or above Nyquist rather than allowed to alias. An aliased sine is silently not the signal its filename claims, which is worse than an error, and the filename is what a procedure written against these files refers to.

## Status

The tool is adopted, parameterised and validated. It reproduces the signal set it came from bit-identically, and the verification has been seen to fail on four injected faults rather than merely assumed to work.

Remaining work is in the other repository and is tracked separately: `cboone/fosforo` still carries `scripts/make-test-tones`, its `.editorconfig` still names that file in the shell brace list, and two plan documents in its `docs/plans/done/` reference the script by path. Those are historical records, so a pointer note is more appropriate there than a rewrite.

The obvious extension, if something needs it, is verifying frequency as well as peak. Nothing currently checks that a file rendered at 200 Hz is at 200 Hz, so a synthesis bug producing the right peak at the wrong frequency would pass. Counting periods on a display is the only thing that catches it today. Do not add it speculatively; add it when something needs it, and give it the same treatment as the level check, which is a bound that cannot reject a correct file.
